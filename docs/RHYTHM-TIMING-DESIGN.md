# 音楽ゲームの入力・曲時計・判定基盤

2026-09-13 レビュー改訂。以下のAPIは新設予定であり、実装済み・実機検証済みを意味しない。対象はまず Windows の単一プレイヤー、単一操作デバイス、少数レーンの譜面とする。判定幅、譜面形式、目標遅延は対象ゲームと実機を決めてから確定する。

## 現状と結論

- `IInput` は状態と押下/解放を公開し、`KeyEdgeBuffer` は内部に蓄積した押下回数を論理フレームへ順次公開する。イベント発生時刻、元の順序、デバイスIDは渡さない。現在の `KeyInput` はUIや通常のゲーム操作に残し、判定専用のイベント列を並設する。
- `GameRunner` の固定更新はキャッチアップ数を制限して経過時間を捨てる。演出には妥当な防御だが、曲と判定の時計には使わない。
- `Sound.Time` はミリ秒単位のバックエンド依存値であり、RayLibのSfxでは経過時間による推定値を含む。対応する高精度時計の時刻、出力待ちサンプル数、取得品質を含まない。現状のまま「音声デバイスに同期した判定」と呼ばない。
- 合成音楽用の `Audio/Bgm/Score` は譜面の判定モデルではない。譜面・判定は音声再生からも描画バックエンドからも独立した Rhythm モジュールの機能とする。

入力・曲時計・判定は **時刻付き入力 → 曲上の時刻への変換 → 判定** の一続きとして実装する。ゲームの `Update` 呼び出し回数や描画フレーム番号を、判定時刻の代用にしない。

## 時刻の契約

単調増加する高精度時計の整数 tick を入力時刻と相関の基準にする。Windows のイベントを受けた場所で、可能な限り早く時刻を採る。OS通知を受けた時刻は物理スイッチの接点時刻ではないため、その差と揺らぎは実機で測る。ハードウェア時刻を提供するデバイスは、その時刻の出所と精度を別に保持する。

再生側は、少なくとも「実際の再生位置に対応するサンプル番号、同時点の高精度時計 tick、サンプルレート、再生世代、状態」を一組で観測可能にする。判定時には近接する有効な観測値からイベント tick を曲上のサンプル位置へ写し、補正量を適用する。長い観測空白、アンダーラン、デバイス切断、Pause/Seek/速度変更をまたいで無条件に外挿しない。再生世代と対応区間を分けて旧イベントとの誤結合を防ぎ、観測品質を記録する。

Windows の WASAPI では [IAudioClock::GetPosition](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition) が位置と対応するQPC時刻を取得する入口になる。共有モードでは [IAudioClock2::GetDevicePosition](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock2-getdeviceposition) も検討できる。再生キューの [GetCurrentPadding](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-getcurrentpadding) は位置との関係を検証する材料になる。ただし、RayLib/DXLib が再生ストリームを所有する現状では、これらを追加で呼ぶだけで当該曲のサンプル位置と結び付くわけではない。精密な曲時計とサンプル指定のキー音が必要なら、描画バックエンドから独立した音声再生層が曲の出力を所有する構成を第一候補とする。`Sound.Time` は一般用途に残す。

音声デバイス位置とスピーカーから聞こえる時刻は一致しない。出力遅延、入力遅延、表示遅延は分けて測り、曲・譜面オフセット、入力補正、表示補正を別パラメータにする。補正を一つの万能オフセットへ畳み込まない。

## 最小APIの境界

| 境界 | 保持するもの | 役割 |
| --- | --- | --- |
| `TimedInputEvent` | tick、単調増加の連番、デバイスID、物理コード、押下/解放、時刻の出所 | OS/デバイス入力を受けた瞬間に記録する。文字入力・IMEとは分離する |
| `ITimedInputSource` | 時刻順イベント列、キューあふれ数、接続状態 | 状態ポーリングとは別経路で判定側へ渡す。あふれは判定の信頼性低下として報告する |
| `IAudioTransport` | 曲のサンプル位置と時計 tick の組、レート、世代、停止/障害状態 | 曲時刻、Pause/Seek/Resume、再生要求、可能ならサンプル指定の発音を扱う |
| `RhythmChart` | 正規化済みのノート時刻、レーン、種類、譜面識別子 | BPM変化などはロード時に一意な整数時刻へ変換する |
| `JudgeSession` | ノート状態、入力順序、補正設定、判定結果 | 正規化入力、確定境界、制御イベントから判定する。描画や固定更新に依存しない |

曲・ノートの時刻表現は `long` のマイクロ秒、音声出力予約はサンプルフレームとし、変換時の丸め規則は後述の契約に従う。キーごとの時刻付き押下・解放を保ち、連打や長押しで `KeyEdgeBuffer` の「1更新1件」の表現に戻さない。キューあふれ時は件数と影響範囲を出し、完全な判定結果やリプレイと偽らない。

判定はレーン内の候補選択、1入力が消費できるノート数、同時刻の並び順、早押し・遅押しの境界、押下/解放、長押し途中の断線、無入力Missを規則として明文化する。入力の到着が遅れても、元のイベント時刻で判定し、到着前に仮のMissを表示した場合は確定規則に従って更新する。無限に待つこともできないので、入力遅延の分布を測定して運用上の確定猶予を設ける。観測最大値は将来の遅延の上限保証ではない。音として過去へ戻って発音することはできないため、遅着したキー音は遅れ量を計測して即時再生または破棄する規則を別に決める。

リプレイには時刻付きイベント、譜面/音源の識別子、時刻変換に必要な曲開始・再生世代・補正・判定設定を記録する。保証範囲は「同じ入力から同じ判定結果」であり、画素や音声波形の一致とは分ける。

## 実装順と合格条件

1. **判定の純粋ロジック**: 1譜面形式・1操作系で押下、解放、連打、同時押し、長押し、Missを実装する。境界値、同時刻、重複、曲停止/再開、譜面のBPM変化と停止、記録した入力列を再読込するリプレイをテストする。同一入力列から同一結果が得られることを確認する。
2. **イベント採取**: Windows のメッセージ/デバイス入力から受信時刻・物理コード・デバイスIDを採り、Rhythm のキューへ運ぶ。既存のUI入力は維持する。短い押下、複数レーン同時押し、連打、描画/更新の停止、キューあふれを実機と自動テストで検証する。
3. **曲再生と時計**: 音声ストリームを所有する再生層を追加し、デバイス位置と高精度時計を対応付ける。Pause/Seek/Resume、曲頭/曲末、アンダーラン、切断/復帰で世代と信頼性を管理する。表示用の `Sound.Time` から判定が値を取らないことを確認する。
4. **縦通しと計測**: イベント→曲時刻→判定→キー音→描画を一本通す。0/16/50/100/1000msの描画停止、30/60/120/240fps、長時間再生で判定の一致、取りこぼし件数、曲時刻のずれを測る。対象デバイスで入力から判定、音声出力、表示までの遅延と分布を物理測定し、採用する判定幅に対する合格値を決める。

最初の縦通しは Windows と一つの再生方式に絞る。RayLib/DXLib は描画・一般ゲーム入力のバックエンドとして維持し、判定結果が描画バックエンドによって変わらないことを比較する。制作エンジン側にはこの判定・譜面・リプレイ契約を利用可能にし、編集UIは縦通し後に設計する。

## レビューで具体化した契約

### 時刻の単位・変換

Rhythmの曲時刻はデバイスに依存しない `long` のマイクロ秒を採用し、負値をプリロールに許す。前述のサンプル位置案は音声層の観測・出力予約に限定する。tickには周波数を添え、乗除算の中間オーバーフローを防ぐ。丸めは最近接・中間は偶数側で統一する。BPM区間は有理数で累積して最終変換時に丸め、譜面停止と同一拍のノートが停止前/後のどちらに属するかを形式仕様に固定する。未対応のワープや負BPMはロード時に拒否する。

- `IAudioClock::GetPosition` の位置はサンプルフレームとは限らず、`GetFrequency` で秒へ換算する。返却QPCは **100ns単位** なので、生の `Stopwatch.GetTimestamp()` と直接減算しない。`S_FALSE` は品質低下として記録し、再試行は有限回にする。[Microsoft仕様](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition)
- `IAudioClock2::GetDevicePosition` は共有モード用。位置はデバイスフレーム、QPCは100ns単位であり、デバイスとクライアントのレート差を扱う。[Microsoft仕様](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock2-getdeviceposition)
- `GetCurrentPadding` はレンダー用バッファの未再生フレーム数で、曲位置や物理出力遅延そのものではない。別時点の位置から無条件に減算しない。[Microsoft仕様](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-getcurrentpadding)

再生層はデバイス位置→出力ストリーム位置→曲時刻の対応区間を保持し、先頭無音、リサンプル、Seek、速度変更、アンダーランの無音を区別する。有効な一定速度区間での基礎式は `songUs = anchorSongUs + (eventTick - anchorTick) * 1_000_000 * speed / tickFrequency` とし、速度は有理数で保存し、最後に丸める。これは対応付け済み曲アンカーからの推定式である。

観測には有効tick範囲、品質、推定誤差、最大外挿時間を付ける。期限超過、逆行、障害をまたぐ観測は判定に使わずセッションを中断して記録する。各しきい値は実機測定後に確定する。

### 再生境界・採取の独立性

再生世代はSeek、再開始、デバイス再構築で更新する。Pause/Resume/速度変更は同一世代内の対応区間IDで区別し、音声側で実際に効いたtickを境界とする。区間は開始を含み終了を含まない。遅着入力は消費時の世代ではなくイベントtickの属する履歴へ対応付け、履歴外は失効とする。Seekでは旧判定セッションを閉じて新規作成する。Pause中は採点せず保持状態を解除し、Resume後は新しい押下を要求する。長押し途中のPauseは試行の中断とする。

描画停止中にも受信時刻を保つには入力のメッセージ処理自体が独立して動く必要がある。停止後にメインスレッドで通知を処理してtickを採っても、停止中の物理発生時刻は復元できない。Windows実装では専用受信スレッドとウィンドウを候補とし、入力登録やフォーカスと既存UI入力との競合を検証して採用する。方式確定前に描画停止への耐性を保証しない。

連番は単一の発行点で付け、正規化tickと連番で順序を決める。デバイスIDは接続セッション内の識別子とし再接続で更新する。OSキーリピートは新規押下にしない。フォーカス喪失・切断・キュー欠落で保持状態を解除し、合成解除の理由を記録して採点入力と区別する。あふれは欠落件数・連番範囲・検出tickを保存し、試行を不完全として中断する。採取スレッドを判定や描画待ちで塞がない。

### 確定・補正・リプレイ

補正の符号は `errorUs = mappedSongUs + inputCorrectionUs - (noteUs + chartOffsetUs)` とする。負が早押し、正が遅押し。100msのノートに90msの入力、入力補正+10msなら誤差0。表示補正は採点式へ入れない。

判定器は描画から独立した `AdvanceTo(watermark)` を持つ。猶予内のイベントを順序付けて処理してから、同範囲の無入力Missを確定する。watermark以下は確定済みとし、後から到着した同範囲の入力は遅着違反として記録する。確定結果を変更せず試行を不完全にする。仮表示は採点結果と分離する。ライブのwatermarkは現在tickから猶予を引いた時刻を曲時刻へ変換し、無効な観測では進めない。曲末も最終ノートの遅判定幅と猶予を消化してから終了する。

最初の候補選択は同レーンの判定窓内で最も早い未消費ノート、同時刻はノートID順、1押下で1ノートとする。窓の両端は包含し、Missは遅側端を超えて確定する。長押し終了窓・途中解放・同一レーンへの複数キー割当は版管理済み設定とし、未設定で長押し対応完了にしない。

リプレイには形式・判定器の版、譜面/音源の内容ハッシュ、レーン割当、丸め・補正・判定設定を保存する。入力ごとの生tick/周波数/出所/連番に加え、判定に使用した正規化曲時刻、世代・区間ID、確定操作、制御イベント、失効・欠落・遅着違反も保存する。再生では保存済みの正規化入力と確定操作を使い、現在の音声時計で再変換しない。時計変換を検証する記録には観測履歴と対応区間も含める。

## 改訂の検証範囲と実装時の合格条件

今回のレビューでは `Core/Input.cs`、`Core/KeyEdgeBuffer.cs`、`Core/InputStep.cs`、`Core/Game.cs`、`Core/Sound.cs`、両バックエンドのSound実装を照合した。KeyEdgeBufferは内部に押下回数を保持するがIInputは回数を公開せず、保留上限もある。採取間の未観測の打鍵は復元できない。WASAPIの単位は上記一次資料で確認した。本改訂は設計文書の検証であり、次表は未実装部分に課す合格条件である。

| 検証 | 合格条件 |
| --- | --- |
| 単位変換 | 10MHz以外のtick周波数、44.1/48kHz、負時刻、長時間値で期待する丸め結果になりオーバーフローしない |
| 判定境界 | 各窓の端と±1µs、同tick、重複連番、無入力、長押し中断を固定期待値と比較する |
| 遅着・確定 | 消費バッチを変えても猶予内で同一結果。猶予超過は違反として検出し確定済み結果を変えない |
| 再生制御 | Pause/Seek/Resume境界の前・同tick・後、速度変更、切断で区間へ誤結合しない |
| リプレイ | 再読込後のノートID・判定・誤差・最終スコアが完全一致する |
| 描画負荷 | 指定fps/停止時間で同一の正規化入力への判定は完全一致。実入力は別に件数・時刻誤差・遅着率を測る |
| 故障注入 | 欠落、時計逆行、観測停止、アンダーランで不完全/中断を検出し正常成績として終了しない |
| 実機測定 | デバイス、出力方式、バッファ、測定件数、中央値/p95/p99/最大値を記録し、事前に決めた誤差・遅延予算を満たす |

合成入力の一致は物理入力時刻や可聴遅延の証明ではない。実機許容値、外挿期限、確定猶予、長押し規則は未決定であり、その確定と測定結果をもって縦通しの採用可否を判断する。

## 2026-09-13 実装状況

初期実装を追加した。完成済みの範囲と、製品採用前の残件を分ける。

- `Rhythm/Timing.cs`: 整数時刻変換、品質付き時計区間、時刻付き入力キューと欠落範囲。
- `Rhythm/ChartTiming.cs`: 有理数BPM、同一拍のノートより前に適用する停止、整数µsへのコンパイル。
- `Rhythm/JudgeSession.cs`: タップ・解放・長押し・Miss、確定watermark、重複/遅着違反、正規化入力のJSONリプレイ。
- `Rhythm/WindowsRawInputSource.cs`: 明示的に起動する専用Raw Input受信スレッド。既存キーボードRaw Input登録がある場合は拒否し、通常のUIキー通知を抑制しない。再接続時のID更新、フォーカス喪失時のResetを扱う。
- `Rhythm/WasapiTransport.cs`: 描画から独立した共有モードWASAPIスレッド、ステレオfloat PCM、音声時計とQPCの対応、Pause/Resume/Seek、サンプル位置指定のキー音ミックス。過去の発音予約は次の書込み可能位置へ移し、遅れをフレーム数で返す。
- `Rhythm/RhythmSession.cs`: 入力→曲時計→判定の接続。最初の対象入力デバイスを選択し、別デバイスを無視する。世代変更・Pauseは試行中断として扱い、再開には新しいセッションが必要。
- `Sandbox/RhythmDemo.cs`: シーン12の4レーンデモ。物理キーD/F/J/K、24ノート、別スレッドの判定、音声時計によるスクロール。

初期実装の制限:

- 判定窓100ms、入力確定猶予50ms、最大外挿250ms、音声要求バッファ100msはデモ用の暫定値。競技向けの遅延・精度を保証する値ではない。
- PCM配列からの再生を実装した。ファイルのデコード、速度変更API、切断後の自動復旧は未実装。切断・アンダーランは故障として試行を停止する。
- ライブ接続は直近の観測だけを保持し、期限外の遅着入力を中断扱いにする。Pauseをまたぐ採点継続や任意の過去区間の再構成は未対応。
- リプレイは正規化入力と確定操作による判定再現に対応。生入力traceはメモリ上で取得可能だが、全観測履歴・接続イベント・内容ハッシュ検証を含む永続化形式の完成は残件。
- 無入力でも曲末後の遅判定を確定できるよう、音声ストリームは無音を継続する。呼出側が試行完了後にDisposeする。デモはこれを実施する。

## Rhythmモジュールへの分離

リズム関連6ファイルは `Rhythm/AstrumLoom.Rhythm.csproj` に集約した。
