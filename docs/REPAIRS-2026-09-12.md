# AstrumLoom 修正・検証記録 — 2026-09-12

[監査記録](REVIEW-2026-09-12.md) の再現可能な不具合を中心に修正した。入力・非同期資源・音声・描画・リプレイ・テスト基盤を対象とする。アーケード品質の音楽ゲーム基盤や制作エディタが完成したという意味ではない。

## 主な変更

- キャッチアップ更新で同じ押下を複数回判定しない。キー保持時間は論理ステップで進める。マウスはメインスレッドで採取し、更新スレッドでは確定済みデータを読む。短いクリック・ドラッグ・ホイールの消費を修正。両パッドの短い押下も既存の共通バッファで保持し、DxLibのデバイス一覧読み取りをロックする。
- 非同期ロードの状態取得からネイティブ生成を分離。メインループが保留中ロードを進め、破棄後の完了通知で状態が復活しない。終了・タイムアウトでも各資源の解放処理を呼ぶ。
- RayLibの効果音はSound、ストリームはMusicだけを生成し、二重生成・全曲の不要な展開を除去。Soundラッパーはメインループで更新され、DrawやPlayStreamの呼び忘れでストリーム更新が止まらない。再Playは先頭から、明示的な開始前シークは保持する。16ms以下のシークを捨てない。
- Audioの再生要求とロード待ちを制限し、拒否数を公開。ロード待ちの期限は実時間で判断し、同じフレームに複数回Updateしても期限を二重加算しない。音声APIの処理自体はメインスレッドに残る。
- Skin.Unloadと終了時の解放を追加。ロードし直す際にテクスチャ・サウンド・数字・所有フォント・Exo資源を解放し、参照キャッシュも消す。シーン切替の強制GCを除去し、渡された子シーンをEnable前に追加する。
- Textureの一時描画オプションで本体の状態を変更しない。XY倍率でサイズを計算し、未ロード時のゼロ除算を避け、Disposeを重複実行してもネイティブ破棄は一度にする。ファイル以外のCloneは未対応を明示する。RayLibのRGBA入力の長さもネイティブAPI呼出前に検証する。
- 両バックエンドで入れ子の描画先を例外時に復元。RayLibではRenderTextureの破棄が描画先を解除するため、破棄後に外側へ復帰する。図形のBlendも適用する。RayLibのテクスチャ寸法にもDefaultScaleを適用し、VSyncはネイティブの垂直同期フラグに接続する。
- TextSpriteのText・Font・Color・装飾の変更を反映し、同サイズの再生成でも旧テクスチャを明示破棄。入力フィルタで拒否された置換が選択文字を消す問題と、Resetのサロゲート分断を修正。
- リプレイのHz・シード・画面サイズを起動前に適用し、シーン生成前に乱数を初期化。記録時は実際のシードを保存する。最初の変更を早く適用する問題、クリック初回の記録漏れを修正し、不正形式・未知キー・設定の矛盾を拒否する。
- 回帰テストをソリューションに追加し、既存ThreadingChecksを追跡対象へ戻す。動画を利用できない検査はPASSに数えずSKIPと記録。実行スクリプトの独自ビルド指紋を除去し、依存・素材の変更判定をMSBuildへ任せる。PS5.1の強制終了フォールバックと出力待ちの上限を追加。

## 検証

Windows実機、.NET SDK 10.0.401、Release構成で確認した。

| 検査 | 結果 | 確認内容・制限 |
|---|---|---|
| ソリューションビルド | 警告0 / エラー0 | 復元済みの依存関係を使用 |
| RegressionChecks | 40 PASS / 0 FAIL | 入力、文字編集、ロード中キャンセル、タイムアウト、リプレイ、資源解放、テストのSKIP集計 |
| ThreadingChecks | 9 PASS | キュー上限・集約・FIFO・並行公開 |
| ネイティブ / RayLib | 10 PASS / 0 FAIL | 音声更新、再Play、5msシーク、Sound/Music所有分離、入れ子描画の復元、加算合成の画素 |
| ネイティブ / DxLib | 7 PASS / 0 FAIL | 音声更新、再Play、5msシーク、入れ子描画の復元、加算合成の画素 |
| Sandbox / RayLib | 43 PASS / 0 FAIL / 7 SKIP | 2217フレーム、8枚。動画の外部プロセス起動に失敗したため動画再生7項目は未検証 |
| Sandbox / DxLib | 50 PASS / 0 FAIL / 0 SKIP | 2217フレーム、8枚 |

音声テストは無音WAVを実際のデバイスで再生し、描画を呼ばずメインループのサービスで時刻が進むことを確認した。DAC出力の遅延、入力から音が出るまでの遅延、物理打鍵の精度を測定したものではない。5msの試験はシーク要求が捨てられないことの確認で、デコーダやデバイスのサンプル精度を保証しない。実IME変換、DPI・全画面・全パッド機種・長時間耐久は今回未検証。Sandboxの図形スクリーンショットも両方確認したが、既存のフォント表示・見出し重なり・グラデーションのバックエンド差は残る。

音楽ゲーム用途の次の必須段階は、時刻付き入力・曲時計・判定・リプレイを同じ時間軸へ接続すること。今回直した状態入力や画面用タイマーだけで、アーケード品質の判定基盤を構成したとは扱わない。
